# Filament → PanelKit terminology map

For developers (and AI agents) who know Filament and are learning PanelKit.
**This is not a compatibility table** — a row here means "this is the
concept's PanelKit name," never "these two APIs behave identically." Only
verified equivalents are listed; anything without one says so rather than
guessing.

> Knowledge of Filament does not imply API compatibility with PanelKit. If
> you recognize a concept from Filament, look up its PanelKit name below (or
> in the [docs](../../docs-site/getting-started/) / [API reference](../../docs-site/api/)) —
> never assume the property or method name carries over unchanged.

| Filament concept | PanelKit concept | Important difference |
|---|---|---|
| `Resource` | `Resource` | Same role, different API surface — check the [API reference](../../docs-site/api/classes/resource), don't assume a method name transfers |
| `$navigationIcon` | `$icon` | **Do not use the Filament property name.** `panel:doctor` specifically detects `$navigationIcon` as a mistake. |
| `$navigationGroup` | `$group` | Same warning as above |
| `$navigationSort` | `$sort` | Same warning as above |
| Relation manager (one concept) | `RelationManager` — **two configurations** | Filament's relation managers are one shape; PanelKit splits into simple (`->related()`) vs. resource-backed (`->resource()`) with materially different capabilities — see [Relation Managers](../../docs-site/relation-managers/) |
| *(no distinct Filament concept — relation managers cover this)* | Nested `Resource` (`$parent`/`$parentColumn`) | A third, independent mechanism in PanelKit: a full routed child resource, not a tab on the parent's page — see [Nested resources](../../docs-site/resources/nested-resources) |
| Infolist | Infolist | Same name, independent data-selection mechanism — see [Infolists](../../docs-site/infolists/) |
| `TextInput` | `TextField` | Every Filament form component is named `{Thing}` in Filament and `{Thing}Field` in PanelKit — a consistent, mechanical rename, not a coincidence to rely on for the handful of PanelKit-only fields |
| `Select` (relationship helper) | `SelectField::relationship($model, $titleAttribute)` | Takes a **model class and one attribute name**, never a dot-notation relationship path — see [Selects & relationships](../../docs-site/forms/selects-and-relationships) |
| Dot-notation relationship access (e.g. in a global-search attribute list) | **Not supported anywhere in PanelKit** | Neither forms, infolists, nor table columns parse a dotted key as a relationship path. Use an explicit join + `->from('table.column')` instead — see [Common failure patterns](../../docs-site/ai/common-errors) |
| `TextColumn` | `TextColumn` | Same name; PanelKit keeps `BadgeColumn`/`TagsColumn` as separate classes rather than folding them into formatting options on `TextColumn` |
| `live()` / `$get()` / `$set()` | `Field::live()` / `afterStateUpdated()` | Same outcome (reactive cross-field dependencies), reached over an Inertia round-trip rather than a Livewire property-mutation cycle — see [Forms — Live fields](../../docs-site/forms/#live-fields) |
| CreateAction / EditAction / ViewAction / DeleteAction | Real routed pages, generated by `Resource` | PanelKit does not have attachable "open the create form" action objects for its own CRUD — the pages already exist and are routed; don't generate or reference these Filament class names |
| Import / Export actions | `panel-operations` (optional package) | Not part of core `alxtexh-enterprise/panel` — verify the package is installed before assuming an importer class exists. See [AI Blueprint — SaaS blueprint](../../docs-site/ai/saas-blueprint) |
| Tenancy (`HasTenants`, tenant switcher) | `TenantContext` / `TenantScope` | PanelKit ships its own native tenancy abstraction (four modes) rather than being tenancy-agnostic-by-default; multi-database isolation specifically still depends on `stancl/tenancy` — see [Authorization — Tenancy](../../docs-site/authorization/#tenancy) |
| Multi-factor authentication | `Panel::twoFactorChallenge()` / `requireTwoFactor()` | Same two provider types (TOTP + email OTP) — one of the closer 1:1 matches in this whole table — see [MFA & passwordless](../../docs-site/authentication/mfa) |
| Render hooks (~57 named positions) | `RenderHooks` (12 named positions) | Same purpose, a deliberately smaller enumerated surface — see [Vue extension points](../../docs-site/extending/vue-extension-points) |
| Panel plugin / standalone plugin | `PanelPlugin` / `Plugin` | Similar two-tier concept; see [Plugins](../../docs-site/extending/plugins) |
| `wire:navigate` (SPA mode) | Inertia (always SPA-transport) | No equivalent toggle needed — PanelKit's transport is Inertia by construction, not an opt-in mode on top of full-page loads |
| Livewire component testing (`livewire()`, `Livewire::test()`) | `InteractsWithPanels` trait | Ordinary HTTP/Inertia request assertions, not a component-testing harness — see [Testing](../../docs-site/testing/) |
| CSS hooks (semantic classes on Blade views) | No direct equivalent | PanelKit renders Vue, not server-rendered Blade partials — style via [Customization](../../docs-site/customization/) tokens or a registered Vue component instead |

## No direct PanelKit equivalent (confirmed, not merely unverified)

- Swappable icon packs — PanelKit validates `$icon` against one fixed,
  curated ~60-name list, not a pluggable icon-set system.
- A dedicated Force-delete/Restore action *class* (as opposed to achieving
  the same outcome through `RecordAction`).

## Genuinely unverified — do not assume either way

A handful of Filament concepts (table layout/responsive stacking, "Prime"
static-content schema components, broadcast notification channels for the
bell specifically, custom asset registration, using the Vue kit entirely
outside a panel) were not resolved with enough confidence in this pass to
list a PanelKit equivalent or its absence. See the fuller notes in
[filament-comparison.md](filament-comparison.md) rather than assuming a row
was simply forgotten.
